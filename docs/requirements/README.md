# 需求文档

本目录存放各模块/功能的需求描述文档。

## 目录组织

按功能模块划分子目录，一个模块一个目录：

```
docs/requirements/
├── README.md              <- 本文件
├── erc20-scanner/         <- ERC20 扫描器需求
│   └── token-balance.md
├── sync/                  <- 同步模块需求
├── convert/               <- 转换模块需求
└── rpc/                   <- RPC 查询服务需求
```

## 命名规则

- 目录名与模块名一致，使用 `kebab-case`
- 一个需求一个 `.md` 文件，命名简洁描述功能（如 `token-balance.md`）
- 同一模块多个需求文件放在同一目录下

## 文档模板

```markdown
# 功能名称

## 背景
为什么要做这个功能，解决什么问题

## 需求描述
功能的核心需求，分点列出

## 数据模型
涉及的数据表/字段/索引

## 接口
暴露的 API / RPC 接口

## 非功能需求
性能、可靠性、扩展性等

## 参考资料
相关链接、PR、设计文档
```
